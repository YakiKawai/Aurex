# Правила интерфейса Aurex

## Главное правило

**Мы не рисуем свой интерфейс. Мы описываем список штатными компонентами Telegram.**

Любой новый экран мода строится так:

```java
public class AurexSomethingActivity extends UniversalFragment {
    protected CharSequence getTitle() { ... }
    protected void fillItems(ArrayList<UItem> items, UniversalAdapter adapter) { ... }
    protected void onClick(UItem item, View view, int position, float x, float y) { ... }
}
```

Скруглённые карточки, отступы, разделители, акцентные заголовки, анимации раскрытия
и поведение при смене темы рисует апстрим. Мы только говорим, из каких элементов
состоит список.

## Зачем

1. **Обновления без боли.** Мы не копируем разметку апстрима к себе, значит нечему
   конфликтовать при мерже новой версии Telegram.
2. **Совместимость с темами.** Любая пользовательская тема и любой размер шрифта
   работают сразу и правильно.
3. **Мод выглядит частью клиента,** а не чужеродной вставкой.
4. **Кода в разы меньше.** Нет своих адаптеров, нет ручной нумерации строк,
   нет ручного notifyItemRangeChanged.

## Шпаргалка по элементам (org.telegram.ui.Components.UItem)

| Нужно | Элемент |
|---|---|
| Заголовок секции | `UItem.asHeader(text)` |
| Пояснение под секцией и разрыв между карточками | `UItem.asShadow(text)` |
| Строка-категория с иконкой и значением | `UItem.asSettingsCell(id, icon, text, value)` |
| Обычный тумблер | `UItem.asSwitch(id, text)` |
| Круглая галочка внутри группы | `UItem.asRoundCheckbox(id, text).setPad(1)` |
| Шапка раскрывающейся группы со счётчиком | `UItem.asRoundGroupCheckbox(id, text, "N/M")` |
| Выбор из нескольких вариантов | `UItem.asRadio(id, text)` |
| Ползунок с числовым значением | `UItem.asIntSlideView(...)` |

## Запрещено без веской причины

- Свои XML-макеты и свои `RecyclerView.Adapter` для списков настроек.
- Жёстко заданные цвета вместо `Theme.getColor(...)`.
- Размеры в пикселях вместо `AndroidUtilities.dp(...)`.
- Элементы интерфейса без реализованной за ними логики.

Если нужного элемента в `UItem` нет — сначала ищем, где похожее уже сделано в апстриме,
и только потом делаем своё — через `UItem.asCustom(view)`, чтобы остаться внутри общей системы.
