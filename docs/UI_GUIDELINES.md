# Правила интерфейса Aurex

## Главное правило

**Мы не рисуем свой интерфейс. Мы описываем список штатными компонентами Telegram.**

Если речь идёт о дизайне, ориентир всегда один — фирменная стилистика Telegram.
Собственные дизайнерские решения не допускаются без веской причины, проговорённой отдельно.
Если что-то выглядит не так, как в штатном клиенте — это не вопрос вкуса, а признак
того, что где-то не задействован штатный механизм. Надо искать его в апстриме,
а не подгонять внешний вид руками.

## Шаблон любого экрана

```java
public class AurexSomethingActivity extends UniversalFragment {

    @Override
    public View createView(Context context) {
        final View view = super.createView(context);
        listView.setSections();                     // скруглённые карточки: dp(12) отступ, dp(16) радиус
        listView.adapter.setApplyBackground(false); // фон рисует секция, а не сами ячейки
        actionBar.setAdaptiveBackground(listView);  // шапка подстраивается при скролле
        return view;
    }

    protected CharSequence getTitle() { ... }
    protected void fillItems(ArrayList<UItem> items, UniversalAdapter adapter) { ... }
    protected void onClick(UItem item, View view, int position, float x, float y) { ... }
}
```

Этот блок `createView` — **обязательный минимум для каждого нового экрана**. Без него
список рисуется в старом стиле — белыми прямоугольниками во всю ширину:
`UniversalFragment` не вызывает `setSections()` сам. Все три строки нужны вместе.
Паттерн взят из апстрима: `PasskeysActivity`, `StickersActivity`, `TimezoneSelector`,
`CallLogActivity`, `LogoutActivity`.

Вызываем именно `setSections()` без параметров, чтобы фирменные значения отступа и
радиуса приходили из апстрима и обновлялись вместе с ним. Свои числа не подставляем.

## Зачем

1. **Обновления без боли.** Мы не копируем разметку апстрима к себе, значит нечему
   конфликтовать при мерже новой версии Telegram.
2. **Совместимость с темами.** Любая пользовательская тема и любой размер шрифта
   работают сразу и правильно.
3. **Мод выглядит частью клиента,** а не чужеродной вставкой.
4. **Кода в разы меньше.** Нет своих адаптеров, нет ручной нумерации строк,
   нет ручного notifyItemRangeChanged.

## Шпаргалка по элементам (org.telegram.ui.Components.UItem)

| Нужно | Элемент |
|---|---|
| Заголовок секции | `UItem.asHeader(text)` |
| Пояснение под секцией и разрыв между карточками | `UItem.asShadow(text)` |
| Строка-категория с иконкой и значением | `UItem.asSettingsCell(id, icon, text, value)` |
| Обычный тумблер | `UItem.asSwitch(id, text)` |
| Круглая галочка внутри группы | `UItem.asRoundCheckbox(id, text).setPad(1)` |
| **Шапка раскрывающейся группы: переключатель справа + счётчик и стрелка** | `UItem.asExpandableSwitch(id, text, "N/M")` |
| Шапка группы без переключателя (круглая галочка слева) | `UItem.asRoundGroupCheckbox(id, text, "N/M")` |
| Выбор из нескольких вариантов | `UItem.asRadio(id, text)` |
| Ползунок с числовым значением | `UItem.asIntSlideView(...)` |

Две последние шапки похожи названиями, но это **разные ячейки**:

- `asExpandableSwitch` -> `VIEW_TYPE_EXPANDABLE_SWITCH` -> `TextCheckCell2` — есть настоящий
  switch справа. Это наш вариант по умолчанию для группы с общим выключателем.
- `asRoundGroupCheckbox` -> `VIEW_TYPE_ROUND_GROUP_CHECKBOX` -> `CheckBoxCell` — switch'а нет
  в принципе, только круглая галочка.

Разделение кликов в раскрывающейся группе:

- нажатие на сам переключатель — `setClickCallback(...)`, включает/выключает режим;
- нажатие на строку — `onClick(...)` фрагмента, раскрывает/сворачивает список.

## Иконки категорий

Векторные drawable в `res/drawable/`, именование `msg_aurex_*.xml`.

- **Цвет путей всегда белый** (`#FFFFFF`). `TextSettingsCell.setIcon` накладывает
  `PorterDuffColorFilter(key_windowBackgroundWhiteGrayIcon, MULTIPLY)`, а MULTIPLY даёт
  `src * tint`: белый исходник превращается ровно в цвет темы, чёрный остаётся
  чёрным и игнорирует тему. Апстрим делает так же, см. `res/drawable/settings_power.xml`.
- Цвет в коде не задаём — его ставит ячейка.
- Размер 26dp при `viewport` 24, контур 1.9, `strokeLineCap="round"`,
  `strokeLineJoin="round"` — фирменные скругления, никаких острых углов.
- `ScaleType.CENTER` — ячейка не масштабирует иконку, размер задаётся самим drawable.

## Запрещено без веской причины

- Свои XML-макеты и свои `RecyclerView.Adapter` для списков настроек.
- Жёстко заданные цвета вместо `Theme.getColor(...)`.
- Размеры в пикселях вместо `AndroidUtilities.dp(...)`.
- Собственные значения отступов и радиусов там, где апстрим уже задаёт фирменные.
- Элементы интерфейса без реализованной за ними логики (заглушки).
- Названия классов и методов апстрима по памяти или по догадке — только после
  чтения исходника.

Если нужного элемента в `UItem` нет — сначала ищем, где похожее уже сделано в апстриме,
и только потом делаем своё — через `UItem.asCustom(view)`, чтобы остаться внутри общей системы.

## Чек-лист перед каждым UI-коммитом

1. Экран наследует `UniversalFragment` и содержит обязательный блок `createView`.
2. Нет ни одного собственного размера, цвета или радиуса там, где есть штатный.
3. Каждый использованный метод апстрима проверен по исходнику, а не по памяти.
4. Каждый элемент в списке действительно работает.
5. Тексты добавлены и в `values/strings_aurex.xml`, и в `values-ru/strings_aurex.xml`.

## Журнал разобранных ошибок

Чтобы не наступать на те же грабли повторно:

| Симптом | Причина |
|---|---|
| Нет главного переключателя у группы | взят `asRoundGroupCheckbox` (`CheckBoxCell`) вместо `asExpandableSwitch` (`TextCheckCell2`) |
| Иконка чёрная и не меняется с темой | пути нарисованы чёрным при `PorterDuff.MULTIPLY` — нужен белый |
| Белые прямоугольники во всю ширину вместо карточек | не вызван `listView.setSections()` |
| Фон ячейки выезжает за скругления | не вызван `adapter.setApplyBackground(false)` |
| `cannot find symbol` на классе TL | имя класса написано по догадке; схема разнесена по `org.telegram.tgnet.tl.*` |
